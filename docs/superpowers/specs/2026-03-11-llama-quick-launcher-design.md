# Llama 快速启动器设计

## 目标

在现有 Windows 便携版 `llama.cpp` 目录中提供一个无需安装依赖的图形启动器。用户双击入口后，可以选择 GGUF 模型、调整常用服务参数、一键启动或停止 `llama-server.exe`，查看实时日志，并快速打开聊天页面或复制 API 地址。

## 范围

### 包含

- Windows PowerShell + WPF 图形界面。
- CMD 双击入口。
- 自动扫描 `models\*.gguf`，同时允许浏览选择其他 GGUF 文件。
- 启动、监控和停止由启动器创建的 `llama-server.exe` 进程。
- 常用参数、高级参数、额外命令行参数。
- 服务就绪检测、实时日志、明确错误提示。
- 自动保存并恢复上次配置。

### 不包含

- 模型下载、转换或量化。
- 多个服务实例的统一管理。
- 远程机器管理。
- API 鉴权和公网反向代理配置。
- 自动性能基准测试或自动重试。

## 技术方案

新增以下文件：

- `启动Llama.cmd`：双击入口，以合适的执行策略和 STA 模式启动 PowerShell 脚本。
- `LlamaLauncher.ps1`：WPF 窗口、配置管理、参数校验、进程生命周期、日志和健康检查。
- `launcher-config.json`：首次保存配置时生成，只记录启动参数。

脚本以自身所在目录作为应用根目录，不依赖用户当前工作目录。它使用同目录的 `llama-server.exe`，默认扫描 `models` 子目录。

## 界面设计

窗口包含四个区域：

1. 模型与服务设置：模型路径、GPU 层数、上下文长度、CPU 线程数、监听地址和端口。
2. 高级设置：批大小、并行请求数、Flash Attention、内存映射、内存锁定和额外命令行参数；默认折叠。
3. 运行控制：启动/停止主按钮、状态文本、打开聊天页、复制 API 地址。
4. 实时日志：合并展示标准输出与标准错误，自动滚动，并限制保留行数。

运行期间锁定会影响命令行的设置。启动/停止按钮保持稳定尺寸，状态变化不引起布局跳动。服务未就绪时，打开页面和复制地址操作保持禁用。

## 默认参数

- 模型：扫描到的第一个 `models\*.gguf`；保存过配置时优先恢复上次模型。
- GPU 层数：`-1`，表示尽可能卸载到 GPU。
- 上下文长度：`8192`。
- CPU 线程数：本机逻辑处理器数量。
- 监听地址：`127.0.0.1`。
- 端口：`8080`。
- Flash Attention：启用。
- 内存映射：启用。
- 内存锁定：禁用。

启动器不根据硬件自动修改用户参数。显存不足等运行错误由 `llama-server` 日志呈现，用户可以调整 GPU 层数或上下文后重试。

## 启动流程

1. 验证 `llama-server.exe` 和模型文件存在。
2. 验证数值范围、监听地址和端口格式。
3. 检查目标端口是否已被占用。
4. 保存当前配置。
5. 以参数数组构造命令行，避免模型路径中的空格造成解析错误。
6. 隐藏子进程控制台，异步捕获标准输出和标准错误。
7. 状态切换为“启动中”，定期探测 HTTP 服务。
8. 探测成功后切换为“运行中”，启用地址相关操作。
9. 若进程在就绪前退出，显示退出码并保留末尾错误日志，恢复设置可编辑状态。

额外命令行参数按 Windows 命令行规则解析；解析失败时阻止启动并提示用户修正。启动器生成的基础参数优先，额外参数不得重复覆盖模型路径、监听地址或端口。

## 停止与退出

点击停止后，启动器先请求关闭服务并等待最多 3 秒；若进程没有退出，则仅按启动器持有的 PID 终止其进程树。停止操作不通过进程名批量查杀，因此不会影响其他 Llama 实例。

关闭窗口时，如果服务仍在运行，弹窗提供两个选择：

- 一并停止服务后退出。
- 保持服务在后台运行并退出启动器。

选择后台运行后，启动器解除对服务生命周期的管理，本次服务只能通过系统工具或其他兼容方式停止。

## 配置管理

`launcher-config.json` 使用 UTF-8 JSON，记录模型路径及全部可编辑参数。配置读取失败、字段缺失或类型不合法时，启动器回退到安全默认值，并在日志中提示；不因配置损坏而阻止窗口打开。

配置使用临时文件后替换的方式写入，降低中途退出造成文件损坏的概率。配置不包含令牌、密钥或其他敏感信息。

## 错误处理

启动前错误通过明确对话框和日志同时展示，包括：

- 可执行文件缺失。
- 模型不存在或扩展名不正确。
- 参数超出允许范围。
- 端口已占用。
- 额外参数无法解析或与受管理参数冲突。

运行时错误保留退出码和日志。启动器在进程存活且服务未就绪时每秒执行一次健康探测，持续显示“启动中”；模型加载不设置硬截止时间，因此不会仅因加载较慢就杀死进程或自动重试。单次 HTTP 探测超时为 1 秒，且始终异步执行，不阻塞 UI。

## 验证方案

- PowerShell 语法解析通过。
- 双击 CMD 能打开窗口，且不依赖当前工作目录。
- 自动扫描模型和浏览选择模型均可用。
- 配置保存后重新打开可恢复；损坏配置可回退。
- 基础参数与高级参数正确映射到 `llama-server` 命令行。
- 模型缺失、可执行文件缺失、无效数值和端口占用均能阻止启动并给出明确错误。
- 使用当前 GGUF 实际启动服务，HTTP 接口可访问，日志持续更新，窗口保持响应。
- 停止后子进程退出且端口释放。
- 关闭窗口时的“停止服务”和“保持后台”两条路径都符合设计。

## 验收标准

用户无需安装 Python、Node.js 或 .NET SDK，双击 `启动Llama.cmd` 即可操作。默认配置下能够尝试加载当前目录内的 GGUF 模型；启动成功后，界面明确显示运行状态与服务地址，可打开聊天页面或复制 API 地址；服务可以从同一窗口可靠停止，常见失败场景有可操作的中文错误信息。
